2. Diagnostic de la Cible

2.1 Périmètre et Règles d'Accès

Aspect de Conformité Analyse & Preuve Technique
Parcours de navigation Exploration structurée : Page d'accueil → Menu Catégorie (path=17) → Pagination HTML → Fiches produit.
Vérification robots.txt Vérification automatique via urllib.robotparser.can_fetch(). Statut : Autorisé (True) pour toutes les URLs explorées.
Restrictions identifiées Le site bloque uniquement les paramètres de pagination invalides (ex. ?page= sans valeur). Les pages réelles (?page=2) sont autorisées.
Politesse et charge Aucun Crawl-delay imposé. Application volontaire d'un délai d'une seconde entre chaque requête HTTP et traitement séquentiel.

2.2 Rendu HTML vs JavaScript

Composant Technique Observation / Preuve Impact sur l'Architecture
HTML Initial (Serveur) Toutes les données (15 produits par page) sont présentes directement dans la réponse HTTP brute. Client HTTP léger (requests) suffisant.
DOM dynamique / JS Aucun composant ni produit n'est injecté dynamiquement après chargement. Inutile d'utiliser Playwright ou Selenium (gain en vitesse et stabilité).
Pagination & Filtres Pagination HTML standard par balises <ul class="pagination">. Suivi direct des liens HTTP GET.

3. Modèle de Données & Normalisation

Champ Type Requis ? Source HTML / Sélecteur Règle de Normalisation & Rejet
id str Non Paramètre product_id dans l'URL Extrait via query string ; None si absent.
name str Oui Listing : h4.title a Nettoyage des espaces ; si absent → Rejet de l'objet.
price float Oui Listing / Fiche : span.price-new Extrait numériquement (ex. $146.00 → 146.0) ; absent → Rejet.
currency str Non Symbole du prix ($, £, €) Mappé vers le code ISO 4217 (ex. USD, GBP, EUR).
category str Non Fiche produit : Fil d'Ariane Avant-dernier maillon du breadcrumb (exclut l'élément actif).
url str Oui Listing : href du lien produit Résolu en URL absolue canonique ; absent → Rejet.
image_url str Non Listing : data-src ou src Résolu en URL absolue ; None si non trouvé.
availability str Non Fiche produit : <li> "Availability:" Normalisé en in_stock, out_of_stock ou preorder.
Règle de Gestion Description Technique
Identifiant & Déduplication Déduplication stricte basée sur l'identifiant product_id. Les doublons ultérieurs sont ignorés et comptabilisés dans les métriques.
Gestion des valeurs manquantes Toute donnée absente est affectée à None (jamais de chaîne vide ""). Un produit sans champ obligatoire est rejeté par build_record().

4. Architecture & Modularité

Module Fichier Source Responsabilité Principale Entrée / Sortie
Configuration src/config.py Chargement des paramètres et variables d'environnement. .env → Objet Config
Acquisition Network src/http_client.py Gestion des requêtes HTTP, politesse et respect de robots.txt. URL → requests.Response
Extraction Pure src/extraction.py Parsing HTML pur sans aucun appel réseau (fonctions pures). HTML string → dict brut
Normalisation & Valid. src/normalize.py Transformation des types, validation des champs requis et déduplication. dict brut → dict normalisé
Exportateur src/export.py Persistance des enregistrements validés en JSONL. dict → data/staging/products.jsonl
Orchestrateur src/scraper.py Enchaînement des étapes, CLI et journalisation centralisée. Arguments CLI → Exécution globale & Logs

5. Ancrage & Stabilité des Sélecteurs

Champ Ancrage CSS Retenu Justification de Stabilité Conduite en cas de Rupture
Nom produit h4.title a dans div.product-thumb Repose sur la classe sémantique OpenCart plutôt que sur la structure de grille Bootstrap fragile. Le champ devient None, le produit est rejeté sans planter et un avertissement est consigné.
Disponibilité <li> contenant le libellé Availability: Ancrage sur le texte métier utilisateur plutôt que sur un index de liste fixe. Le champ prend la valeur None et le scraper continue d'extraire les autres attributs.

6. Choix Technologiques

Besoin Technique Outil Sélectionné Raison du Choix Alternative Écartée & Motif
Acquisition Network requests Léger, rapide et suffisant pour le HTML servi côté serveur. Playwright / Selenium : Écarté car surdimensionné et plus lent.
Parsing HTML BeautifulSoup4 + lxml Syntaxe simple, tolérante aux erreurs de balisage et sélecteurs CSS performants. Regex : Écarté car trop fragile face aux modifications du HTML.
Vérification Hors-Réseau Script autonome (tests/verif.py) Exécution instantanée sur snapshots HTML localisés (fixtures). Tests intégration réseau : Écarté pour garantir la répétabilité sans dépendance Web.
Format de Sortie JSON Lines (.jsonl) Format append-only standard adapté au traitement de données structurées. CSV : Écarté en raison de la mauvaise gestion des valeurs nulles/optionnelles.

9. Limites & Améliorations Futures

Axe / Limite Constatée Description du Comportement Amélioration Proposée
Variabilité de la Catégorie La catégorie affichée dépend de la route d'accès du visiteur (ex. Software vs Tablets pour le produit 28). Conserver l'historique des catégories croisées pour assigner une taxonomie principale.
Reprise sur Incident En cas d'interruption réseau, la collecte doit être relancée depuis le début. Mettre en place un système de checkpoint enregistrant les product_id déjà traités.
